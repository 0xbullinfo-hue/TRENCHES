# STRICT EXECUTION PROTOCOL: ZERO ASSUMPTIONS & HARDENED VERIFICATION

> **CRITICAL DIRECTIVE**: You must NEVER make assumptions, guess constants, hardcode placeholder logic, or create permissive mock shortcuts for any task. Every single fact, constant, on-chain parameter, and integration contract must be empirically validated before writing or changing code.

---

### 1. Zero On-Chain Assumptions
- **Empirical Blockchain Verification**: Never assume token decimals, token supplies, account layouts, or program conventions from memory, templates, or comments.
- **Direct RPC Query Requirement**: Before writing or modifying token/staking math, execute a live RPC call (e.g. `getTokenSupply`, `getAccountInfo`, `getParsedTransaction`) to verify the exact parameters directly on-chain.
- **Exact Precision**: Always use raw integer `bigint` math matching the exact on-chain decimals (e.g. 6 decimals for pump.fun tokens).

---

### 2. Zero Inventions & Strict Fail-Closed Adapters
- **No Fabricated Endpoints or Program IDs**: Never invent program IDs, contract addresses, vault addresses, or fake API structures.
- **Isolate and Flag `BLOCKED`**: If an official program ID, vault key, or API credential is not provided in the environment or official provider docs, isolate the feature behind a clearly defined adapter and immediately flag it as `BLOCKED`.
- **Never Simulate False Success**: An unconfigured provider must fail closed and reject the action. It must never allow users through or simulate successful staking.

---

### 3. Absolute Ban on Leaked Credentials & Fallback Links
- **No Hardcoded Links**: Static invite links, secrets, private keys, or webhook secrets must NEVER appear in code, test files, or `.env.example`.
- **Fail-Closed Invite Generation**: If a dynamic single-use invite cannot be generated by the API, the system must throw an explicit error. It must NEVER fall back to a hardcoded public link that allows unauthorized entry.

---

### 4. Adversity-First Error Handling (Network Error $\neq$ $0 Balance)
- **Distinguish Unreachable vs. Zero**: A network timeout, RPC rate limit, or failed HTTP call is strictly `unknown`, NEVER `free` or `$0`.
- **Protect Users During Downtime**: Any state-altering background job (such as Telegram sweeps, membership evictions, or account downgrades) must immediately skip any user whose status is `unknown`. Never evict or demote legitimate paying members due to an RPC hiccup.

---

### 5. Elimination of Divergent Legacy Calculations
- **Single Source of Truth**: When an authoritative service (such as `entitlements.ts` or `price.ts`) is established, immediately refactor or eliminate all older legacy calculations in sibling files (`db.ts`, endpoints, client components).
- **No Stale Placeholders**: Hardcoded placeholder prices (e.g. `0.0000164`) must never be used as silent production fallbacks. Always use live oracle querying with explicit freshness and error reporting.

---

### 6. Rigorous Test Coverage for Adverse Scenarios
- **Never Test Only the Happy Path**: Tests must explicitly verify:
  1. Network and RPC failure handling (`unknown` status, sweep skipping).
  2. Signature replay prevention and duplicate submission.
  3. Strict boundary thresholds (e.g. \$19.99 vs \$20.00, 89 days vs 90 days).
  4. Token transfer destination verification (ensuring tokens actually entered the program vault).
- **Environment Parity**: Tests must run with active environment parity (`--env-file=.env.local` or identical test secrets). Never alter test secrets to mask authorization failures.

---

### 7. Task Execution Verification Gate
Before declaring any task complete:
1. Run `npm run typecheck` $\to$ must have **0 errors**.
2. Run `npm run lint` $\to$ must have **0 warnings / 0 errors**.
3. Run `npm test` and acceptance tests $\to$ **100% pass rate**.
4. Verify that no secrets, `.env.local`, or corrupted files are committed to git.
